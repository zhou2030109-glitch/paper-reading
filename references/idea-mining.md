# 从论文找可做的研究问题

**仅在用户明确要求时加载**（"有什么 idea 可做""哪里能改进""帮我找选题"）。默认精读不加载本文件。

## 1. 作者没解决什么

先扫三处：Limitation / Future work 段落、failure case、错误分析表。再看两类更值钱的地方：

- **文中明确写了但没测的场景**；
- **被强假设排除掉的问题**（这类作者通常自己不会承认）。

## 2. 每个假设问一次"如果去掉会怎样"

> 如果去掉这个假设，会不会自然长出一个新的研究问题？

这是产出 idea 最稳定的方式：假设 → 去掉 → 新设定 → 新问题。

## 3. 哪个模块最脆弱

对最关键的模块逐个问：可否替换？可否学习化？可否规则化？能否自动验证？能否降成本？

脆弱点通常是下一篇文章的入口——**尤其是"现在靠人工或靠强规则"的那一步。**

## 4. 方法是否只在作者的数据集上有效

检查：OOD、cross-domain、real-world 部署、online / dynamic 环境、规模扩展。

只要其中一条没测，就说明结论有边界，边界外就是空间。

## 5. 提取思想，不要复制实现

最后必须回答：

> **这篇论文最值得借走的研究思想是什么？**

思想类（可迁移）：反馈机制、验证方式、监督信号构造方式、分解问题的角度、评价口径。
实现类（不可迁移）：具体 prompt、具体超参、具体工程胶水。

## 6. 输出格式

给 idea 时用统一格式，避免空谈：

```
问题：一句话
为什么现在做得不好：
可以怎么做（2~3 步）：
怎么验证它真的有用（最小实验）：数据集 / baseline / 指标 / 预期现象
风险与最可能失败的地方：
属于哪条路线：
```

一条"能设计出最小验证实验"的 idea，比十条"很有前景的方向"有用。
