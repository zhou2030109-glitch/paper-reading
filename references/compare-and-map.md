# 多论文比较与研究地图

## 1. 对比表（用户说"几篇一起比"时用）

不要只比跑分：

| 维度 | Paper A | Paper B |
|---|---|---|
| 研究问题 | | |
| 核心假设 | | |
| 输入 / 输出 | | |
| 方法主线 | | |
| 训练方式 | | |
| 推理方式 | | |
| 数据集 | | |
| 指标 | | |
| 泛化能力 | | |
| 计算成本 | | |
| 最大优点 | | |
| 最大问题 | | |
| 适用场景 | | |

表格之后必须回答：**两者本质区别是什么？**（一句话，落在"什么问题设定不同 / 哪一步机制不同"上，不能是"一个用 A 数据集一个用 B 数据集"。）

若两篇数字来自不同 benchmark / split / evaluator，在表里直接标注不可比，不要排座次。

## 2. 研究地图（`notes.md` 里的持久结构）

```text
研究问题
├── 路线 A（核心思路一句话）
│   ├── Paper 1：解决什么子问题 / 留下的缺口
│   └── Paper 2：接着补了什么
├── 路线 B（核心思路一句话）
│   ├── Paper 3
│   └── Paper 4
└── 尚未解决的问题
    ├── Problem 1
    └── Problem 2
```

维护规则：

- 每读一篇就往里挂，**先判断它属于哪条路线，再写它补了什么缺口**；
- 记录继承与竞争关系：谁继承谁、谁在修补谁的漏洞、哪两条路线互相竞争；
- 术语表单独一段：同一概念不同论文的不同叫法（例如 verifier / checker / critic）记下来，避免把同一个东西当成两个创新；
- 目标不是背论文名字，而是知道**当前真正的瓶颈在哪**。

## 3. `paper-notes/<slug>/notes.md` 建议结构

```markdown
# <论文标题>
- slug / arXiv ID / 状态（preprint|accepted|published）/ 核实渠道

## 一句话
## 动机
## 流程
## 真创新
## 模块
## 数据
## 实验（含"衡量不到什么"）
## 证明了什么 / 没证明什么
## 术语表（本文的叫法）
## 挂到哪条路线 + 补了什么缺口
## 可继续研究的问题
```

读第二篇同领域论文时，先读这份文件，再讲新论文——避免把已有结论重讲一遍，也避免前后术语不一致。
